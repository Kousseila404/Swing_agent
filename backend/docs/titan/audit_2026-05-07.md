# CRITIQUE — Validation empirique

Ces 5 défauts ne se résolvent pas par du code. Ils exigent du temps qui passe.
Plan détaillé : [monitoring_plan.md](./monitoring_plan.md).

## <a id="bug-1"></a>#1 — Pondérations piliers calibrées à la main
- **Fichier:** `modules/sector_metrics/_scoring.py:74-115`
- **Constat:** Q22/V18/R13/S18/M18/P11/G13/RV11/I8 issus de 17 "Lots" itératifs. Aucun WFO documenté, aucun IC OOS justifiant les valeurs.
- **Impact:** Alpha volatil, recalibrations ad hoc invalident les backtests précédents.
- **Statut:** report monitoring (gate "ic_test ≥ 0.03 sur 60j" avant re-pondération).

## <a id="bug-2"></a>#2 — WFO calibration cassée
- **Fichier:** `modules/wfo_calibration.py`, `data/wfo_history.jsonl`
- **Constat:** 1 fold, 5 tickers train, IC_test=0.0, surfit Risk=0.35/Momentum=0.65 (les 7 autres = 0). Run prod-grade 2026-05-01 a planté ("moins de 3 paires").
- **Impact:** Aucune calibration empirique des poids piliers. Les valeurs courantes sont déclaratives.
- **Statut:** report monitoring.

## <a id="bug-3"></a>#3 — Zéro trades clos
- **Fichier:** `data/trade_journal.csv`
- **Constat:** 5 trades total, 0 clos (4 OPEN, 1 CANCELED). `performance_attribution` exige ≥ 20.
- **Impact:** Impossible d'attribuer la performance aux piliers, donc impossible de valider l'ordre des poids.
- **Statut:** report monitoring (compteur `n_closed_trades` à exposer).

## <a id="bug-4"></a>#4 — Historique snapshots < 60 jours
- **Fichier:** `data/universe_history/`
- **Constat:** 16 jours d'archives JSON.gz. WFO et backtest statistiquement non significatifs.
- **Impact:** Sharpe 6.66 (artefact), hit rate 28.6 %, alpha +0.16 % non significatif.
- **Statut:** report monitoring (gate `coverage_days ≥ 60` pour backtest "production-grade").

## <a id="bug-5"></a>#5 — Look-ahead bias backtest
- **Fichier:** `modules/backtest.py`
- **Constat:** `publication_lag_days=0` par défaut alors que FMP/yfinance ont T+2 à T+5, 10-K à T+90.
- **Impact:** Alpha sur-estimé de 10–50 bps dans tous les backtests publiés.
- **Statut:** report monitoring + patch ponctuel (`--lag-days ≥ 30` requis).

# CRITIQUE — Bugs scoring

## <a id="bug-6"></a>#6 — Clipping prématuré du composite
- **Fichier:** `modules/sector_metrics/_scoring.py:1119-1128` (avant patch)
- **Constat:** `clip(composite + tilt_adjust)` puis `× dq_coef`. Un ticker à 98 + QARP(+5) = 103 → clip 100 → ×0.95 = 95. Devrait être 103 × 0.95 = 97.85.
- **Impact:** Bonus QARP/GARP/consistency partiellement absorbés par le clip → ranking top-N faussé.
- **Patch:** ✅ cf. hardening §A.6. Ordre corrigé : `clip((composite + tilt) × dq_coef)`.

## <a id="bug-7"></a>#7 — Freshness mesurée sur fetched_at, pas period_end
- **Fichier:** `modules/sector_metrics/_scoring.py:30`
- **Constat:** `_parse_fetched_at_age_days` calcule l'âge du download. Un fetch frais d'un EPS Q3-2024 a `age_days=0` mais `period_end_age=240j`. `data_confidence.freshness=1.0` à tort.
- **Impact:** Piotroski Y/Y, Quality, Value reposent sur des comparables stale sans warning.
- **Patch:** ✅ cf. hardening §A.7. Nouveau `_parse_period_end_age_days` + champs `fundamentals_report_age_days[_y1]` exposés.

## <a id="bug-8"></a>#8 — Stale fallback sans borne dure sur period_end
- **Fichier:** `modules/fundamentals_cache.py:55,282`
- **Constat:** `STALE_FALLBACK_MAX_AGE_SECONDS=7d` borne l'âge du *fetch*, pas du report. Un EPS Y-1 de 14 mois passe le gate.
- **Impact:** Pipeline data_confidence ne pénalise jamais les reports périmés silencieux.
- **Patch:** ✅ cf. hardening §A.8. `PERIOD_END_MAX_AGE_DAYS=200`, `PERIOD_END_Y1_MAX_AGE_DAYS=450`. Tag `report_stale=` propagé via `source_provider="/stale_report"`.

## <a id="bug-9"></a>#9 — Sanitize EV/EBITDA ≤ 0 silencieux
- **Fichier:** `modules/sector_metrics/_scoring.py:789` (avant patch)
- **Constat:** EV/EBITDA et Forward P/E ≤ 0 → None silencieux. Un turnaround story (EBITDA négatif transitoire) disparaît du Value sans signal.
- **Impact:** Biais anti-turnaround invisible côté UI/auto_proposer.
- **Patch:** ✅ cf. hardening §A.9. Comportement scoring inchangé (toujours None) mais nouveau champ `value_unprofitable_flags` listant `ev_ebitda_negative` / `forward_pe_negative`.

## <a id="bug-10"></a>#10 — Piotroski appliqué aveuglément aux Financials/REITs
- **Fichier:** `modules/sector_metrics/_scoring.py:452-524` (avant patch)
- **Constat:** F7 (current_ratio>1), F5 (D/E baisse), F9 (gross_margin) non significatifs pour Financials. F7, F6, F9 non significatifs pour REITs. Tous évalués aveuglément → JPM/MS/O notés à tort.
- **Impact:** Banques structurellement pénalisées, REITs sous-notés.
- **Patch:** ✅ cf. hardening §B.10. `_PIOTROSKI_SKIP_CRITERIA_BY_SECTOR`, dénominateur honnête (`f_score_max=5` Financials, 6 REITs, 9 autres).

## <a id="bug-11"></a>#11 — YF circuit breaker silencieux
- **Fichier:** `modules/yf_circuit_breaker.py`, `data_providers/_fallback.py:214`
- **Constat:** Quand le breaker s'ouvre + cache <7j servi, aucun tag stale → `data_confidence` reste haute.
- **Impact:** L'utilisateur ne sait pas que les recos sont sur du cache stale.
- **Patch:** ✅ Couvert par #8 (`/stale_report`) + endpoint existant `/api/data_health` + `data_confidence._freshness_factor` qui consomme déjà `/stale`.

# IMPORTANT

## <a id="bug-12"></a>#12 — Sector-relative dégénère < 12 tickers
- **Fichier:** `modules/sector_metrics/_scoring.py:304-320`
- **Constat:** Sous 12 tickers, fallback global silencieux. Materials, REITs, Utilities tournent au seuil.
- **Impact:** Scoring intra-secteur instable pour ces secteurs sans signaling.
- **Patch:** ✅ cf. hardening §B.12. Nouveau flag `sector_relative_fallback: bool` exposé.

## <a id="bug-13"></a>#13 — Tilts cumulatifs sans cap
- **Fichier:** `modules/sector_metrics/_scoring.py:145-178, 1054-1117`
- **Constat:** QARP+GARP+consistency = +10 max ; cheap_junk+falling_knife = -16 max. Aucun plafond.
- **Impact:** L'empilement de tilts peut écraser le composite (LEN, KHC, HPQ à -16 observés).
- **Patch:** ✅ cf. hardening §C.13. Cap absolu `_TILT_TOTAL_CAP=8`.

## <a id="bug-14"></a>#14 — Falling_knife double-compte le momentum
- **Fichier:** `modules/sector_metrics/_scoring.py:1072` (avant patch)
- **Constat:** Le pilier Momentum (poids 15 %) capture déjà la baisse. Le `-6` re-pénalise.
- **Impact:** Double-counting partiel.
- **Patch:** ✅ cf. hardening §C.14. Magnitude réduite `-6 → -4`.

## <a id="bug-15"></a>#15 — Cheap_junk redondant avec piliers Q/V
- **Fichier:** `modules/sector_metrics/_scoring.py:1068` (avant patch)
- **Constat:** Q faible (poids 18 %) et V haut (poids 13 %) sont déjà reflétés dans leurs poids respectifs. Le `-10` est partiellement redondant.
- **Impact:** Sur-pénalisation des "value traps".
- **Patch:** ✅ cf. hardening §C.15. Magnitude réduite `-10 → -7`.

## <a id="bug-16"></a>#16 — Revisions + Insider opaques (19 % du composite)
- **Fichier:** `modules/sector_metrics/_scoring.py:935-1022` (Revisions, Insider)
- **Constat:** Revisions (+11 %) court-termiste sur stratégie LT. Insider (+8 %) IC ~0.05/6M selon Lakonishok 2001 mais module `enrich_universe_with_insider()` peu auditable.
- **Impact:** 19 % du composite repose sur signaux à validation faible.
- **Statut:** ⚠️ non-patché. Recommandation : à inclure dans la calibration WFO post-monitoring (cf. #1).

## <a id="bug-17"></a>#17 — All-NaN pilier sans renorm dynamique
- **Fichier:** `modules/sector_metrics/_scoring.py:1024-1052` (avant patch)
- **Constat:** Si Momentum API down → tous tickers `M=50` (count=0) → 15 % du composite contribue à 50 (pull artificiel vers neutre, variance réduite).
- **Impact:** Composite dégénère silencieusement quand un pilier est entièrement vide.
- **Patch:** ✅ cf. hardening §D.17. Renorm dynamique : `composite = Σ w_i × s_i / Σ w_i` sur piliers avec count>0.

## <a id="bug-18"></a>#18 — Consistency bonus sur data sparse
- **Fichier:** `modules/sector_metrics/_scoring.py:1095-1117`
- **Constat:** Bonus +2 si `≥ 6` piliers avec data, σ<15, μ≥55. Un ticker FMP-only avec 6/9 piliers (Sentiment/Revisions vides) peut déclencher bonus.
- **Impact:** Faux signal "balanced excellence" sur tickers data-pauvres.
- **Patch:** ✅ cf. hardening §D.18. Seuil relevé `_CONSISTENCY_MIN_PILLARS_USED=7`.

## <a id="bug-19"></a>#19 — FCF-yield avec mcap≤0 et gate général manquant
- **Fichier:** `modules/sector_metrics/_scoring.py:803-812, 760`
- **Constat:** Le calcul FCF protège déjà mcap≤0, mais `market_cap` n'est pas dans `_TITAN_SCORING_FIELDS` → un OTC defunct (mcap=0) peut passer le DQ gate.
- **Impact:** Penny stocks defunct peuvent atteindre le top Value via EV/EBITDA seul.
- **Patch:** ✅ cf. hardening §A.19. Gate hard `market_cap > 0` ajouté en amont.

## <a id="bug-20"></a>#20 — Cross-provider divergence en log-only
- **Fichier:** `data_providers/_fallback.py:67-91`
- **Constat:** `_check_divergence` log WARNING si écart >5 % FMP/YF, mais info perdue côté API/UI.
- **Impact:** Client aveugle sur `P/E=15 vs P/E=22`.
- **Patch:** ✅ cf. hardening §A.20. Nouveau champ `cross_provider_divergence: list[str]` propagé du provider jusqu'au scored payload.

## <a id="bug-21"></a>#21 — Sector-aware DQ masque les manques
- **Fichier:** `modules/sector_metrics/_scoring.py:232,662`
- **Constat:** Financials exclut 4 fields du DQ → un ticker Financial sans D/E (qui en a normalement) a 100 % DQ malgré le manque réel.
- **Impact:** Cache silencieusement la mauvaise data plutôt que de la mesurer.
- **Patch:** ✅ cf. hardening §B.21. Nouveau `structural_gaps: list[str]` exposant les fields non-applicables mais effectivement absents.

## <a id="bug-22"></a>#22 — Universe gate vérifie le fichier, pas son contenu
- **Fichier:** `modules/auto_proposer.py:231` (avant patch)
- **Constat:** Gate `_gate_universe_freshness` vérifie l'âge de `universe.json`, pas la fraîcheur des fundamentals dedans. 70 % de stale_fallback peut passer.
- **Impact:** Recos basées sur cache stale + reports périmés sans alerte.
- **Patch:** ✅ cf. hardening §A.22. Nouveau `_gate_fundamentals_staleness` (FUNDAMENTALS_STALE_MAX_RATIO=0.30).

## <a id="bug-23"></a>#23 — Piotroski IPO < 2 ans pénalisé
- **Fichier:** `modules/sector_metrics/_scoring.py:614-628` (avant patch)
- **Constat:** Dénominateur fixe 9. Un IPO récente avec 4/4 absolu passing → score=44 % (pénalité structurelle).
- **Impact:** Biais anti-IPO récent.
- **Patch:** ✅ couvert par §B.10 (dénominateur sector-aware). Pour IPO non-Financial/REIT, comportement inchangé (4/9=44 % conserve l'info "données partielles").
